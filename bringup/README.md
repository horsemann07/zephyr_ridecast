# RideCast — STM32H7B3I-DK Bring-Up Guide

**Platform:** Windows PowerShell (native Windows build, **not WSL**)  
**Board:** STM32H7B3I-DK (`stm32h7b3i_dk`)  
**RTOS:** Zephyr v4.5.0  
**Purpose:** Validate the development environment, STM32, serial console, LED, LCD, LVGL and touchscreen **before** integrating CC3351.

> Every terminal command below is on **one physical line**. Run commands in order. Stop at a failed check and diagnose it before moving on. All tests reuse the **same project-root `build/`** directory; the next test overwrites the previous build.

## 1. Check hardware (no code)

1. Verify the silkscreen says **STM32H7B3I-DK**, not STM32F7 or another H7 board.
2. Check that the 480×272 LCD and touch ribbon connections are seated correctly.
3. Connect the board's **ST-LINK USB** connector to the PC with a data-capable cable.
4. Check that Windows detects an ST-LINK device. In **Device Manager**, locate its virtual serial **COM port** under **Ports (COM & LPT)** (if the driver exposes one).
5. Leave **BP-CC3351 disconnected** until after display and touch are verified.

**Pass:** Correct board, good power, ST-LINK detected; record the assigned COM number.

- Zephyr setup: https://docs.zephyrproject.org/v4.5.0/develop/getting_started/index.html
- STM32CubeProgrammer: https://www.st.com/en/development-tools/stm32cubeprog.html

After installing STM32CubeProgrammer, check whether its CLI is on your PATH:

```powershell

```

If that prints nothing, the program may still be installed but its `bin` directory isn't on PATH. Find the installed CLI and add it to PATH before `west flash`.

**Pass:** All build tools work; the STM32CubeProgrammer executable is available to West.

## 3. Check the Zephyr 4.5 workspace

### 3.1 Check the Git submodule

From the project root:

```powershell
git -C zephyr_workspace\zephyr status
git -C zephyr_workspace\zephyr describe --tags --exact-match
git submodule status
```

The desired tag is `v4.5.0`. If the clone is valid but the wrong revision is checked out:

```powershell
git -C zephyr_workspace\zephyr checkout v4.5.0
```

**Important:** You previously encountered a Windows `Permission denied` error while registering the submodule. If `git -C ... status` fails, repair that Git/Windows permission problem **before** proceeding; do not blindly remove and re-download the repository. The Zephyr path should be a valid Git submodule when finished.

### 3.2 Create and activate Python environment

From the project root:

```powershell
py -3 -m venv zephyr_workspace\.venv
.\zephyr_workspace\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip west
```

If the virtual environment already exists, skip the first command. If PowerShell blocks activation, see Microsoft's execution policy documentation; don't run the entire development toolchain in WSL as a workaround.

### 3.3 Initialize West and download modules

```powershell
cd zephyr_workspace
if (-not (Test-Path .west\config)) { west init -l zephyr }
west update
python -m pip install -r zephyr\scripts\requirements.txt
west zephyr-export
```

`west init -l zephyr` uses the Zephyr **Git submodule** as the West manifest source. `west update` downloads the Zephyr-managed modules; those do not each need to be tracked in the RideCast Git repository.

### 3.4 Install/verify the ARM toolchain

```powershell
west sdk install --toolchains arm-zephyr-eabi
west topdir
west list
west boards | Select-String stm32h7b3i_dk
```

If you already installed a compatible Zephyr SDK, you can skip the installation command. Make sure the SDK is a **Windows** SDK, not a Linux/WSL SDK.

**Pass:** West reports the `zephyr_workspace` directory, lists modules and recognizes `stm32h7b3i_dk`.

## 4. First custom application — Zephyr boot + UART + LED

We will create **three small source/configuration files** in `bringup/`, **not** in `app/`.

### 4.1 Create directories/files

Return to the project root:

```powershell
cd ..
New-Item -ItemType Directory -Force bringup\src
New-Item -ItemType File -Force bringup\CMakeLists.txt
New-Item -ItemType File -Force bringup\prj.conf
New-Item -ItemType File -Force bringup\src\main.c
```

Open these files in VS Code, copy the following contents, and save them.

### File: `bringup/CMakeLists.txt`

```cmake
cmake_minimum_required(VERSION 3.20.0)

set(ZEPHYR_BASE "${CMAKE_CURRENT_LIST_DIR}/../zephyr_workspace/zephyr" CACHE PATH "Zephyr source")
find_package(Zephyr REQUIRED HINTS "${ZEPHYR_BASE}")

project(stm32_board_bringup LANGUAGES C)

target_sources(app PRIVATE src/main.c)
```

### File: `bringup/prj.conf`

```ini
CONFIG_GPIO=y
CONFIG_SERIAL=y
CONFIG_CONSOLE=y
CONFIG_UART_CONSOLE=y
CONFIG_PRINTK=y
```

### File: `bringup/src/main.c`

```c
#include <zephyr/kernel.h>
#include <zephyr/device.h>
#include <zephyr/devicetree.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/sys/printk.h>

#define LED_NODE DT_ALIAS(led0)

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(LED_NODE, gpios);

int main(void)
{
    int ret;
    uint32_t count = 0U;

    printk("\n=== RideCast STM32H7B3 bring-up ===\n");

    if (!gpio_is_ready_dt(&led)) {
        printk("ERROR: LED GPIO not ready\n");
        return 0;
    }

    ret = gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);
    if (ret < 0) {
        printk("ERROR: LED GPIO configure failed: %d\n", ret);
        return 0;
    }

    printk("GPIO initialized. Starting heartbeat...\n");

    while (1) {
        ret = gpio_pin_toggle_dt(&led);
        if (ret < 0) {
            printk("ERROR: LED toggle failed: %d\n", ret);
        }

        printk("STM32 alive: %u\n", count++);
        k_sleep(K_SECONDS(1));
    }

    return 0;
}
```

On this board, Zephyr maps `led0` to user red LED **LD1**, and the console is on **USART1** connected to ST-LINK. The board UART defaults to **115200 baud**.

### 4.2 Build and flash

From the project root, with the Python virtual environment activated:

```powershell
cd zephyr_workspace
west build -p always -b stm32h7b3i_dk -s ..\bringup -d ..\build
west flash -d ..\build
```

Open the ST-LINK COM port in PuTTY or another terminal with **115200, 8-N-1, no hardware flow control**. If necessary, reset the board after opening the terminal to see the startup banner.

Expected example:

```text
=== RideCast STM32H7B3 bring-up ===
GPIO initialized. Starting heartbeat...
STM32 alive: 0
STM32 alive: 1
STM32 alive: 2
```

The red user LED should toggle once each second.

**Pass:** The firmware flashes, logs appear, and the LED toggles.

## 5. LCD test — without LVGL

Zephyr already includes a display sample. From **`zephyr_workspace/`**:

```powershell
west build -p always -b stm32h7b3i_dk -s .\zephyr\samples\drivers\display -d ..\build
west flash -d ..\build
```

**Expected:** Color test regions appear on the 480×272 LCD, and an area changes over time. This verifies the display driver, LTDC and framebuffer path. Exact patterns depend on the sample/pixel format.

**Pass:** You see correctly rendered colors and visible updates; no crashes or repeated resets.

## 6. LVGL test

Run Zephyr's supplied LVGL sample, still from **`zephyr_workspace/`**:

```powershell
west build -p always -b stm32h7b3i_dk -s .\zephyr\samples\subsys\display\lvgl -d ..\build
west flash -d ..\build
```

**Expected:** `Hello World` and a counter that increments once per second. If the appropriate touch/pointer input is available in the LVGL configuration, the sample may show an interactive button instead of a plain label.

**Pass:** Text appears and the counter updates steadily without display artifacts or crashes.

## 7. Touchscreen test

Zephyr 4.5 provides a more direct hardware test than relying only on the LVGL button. The board devicetree defines the FT5336 controller on I2C4 and selects it as `zephyr,touch`.

From **`zephyr_workspace/`**:

```powershell
west build -p always -b stm32h7b3i_dk -s .\zephyr\samples\subsys\input\draw_touch_events -d ..\build
west flash -d ..\build
```

**Expected:** Touching different places on the LCD draws a small marker/plus at the corresponding touch location. Check the four corners and middle; the coordinates should not appear inverted or swapped.

**Pass:** The marker follows your finger at the expected positions. If this fails, check the FT5336 configuration and I2C/touch inputs before building a custom LVGL UI.

## 8. Inspect BP-CC3351 — no connection yet

Before electrically connecting the BoosterPack to the STM32:

1. Record the BP-CC3351 PCB revision and inspect all power-supply jumpers.
2. Check host power requirements and logic voltages against the actual BoosterPack hardware guide.
3. Identify **Wi-Fi SPI**: CLK, MOSI, MISO, CS, IRQ and reset.
4. Identify **BLE UART HCI**: TX, RX, RTS, CTS and any additional enable/interrupt signals specified by TI.
5. Confirm the STM32 interface pins are free and accessible. Cross-check both board schematics before wiring.
6. Do **not** attach both boards or power the BoosterPack until those checks pass.

TI hardware guide: https://software-dl.ti.com/simplelink/esd/simplelink_wifi_sdk/10.10.01.08/exports/docs/WiFi-toolbox/html/cc33xx/BP-CC33X1_HW_UserGuide.html

**Pass:** Recorded connector mapping and safe power plan. Integration comes later.

## Common problems

| Problem | First checks |
| --- | --- |
| `zephyr_workspace/zephyr/.git Permission denied` | Fix Git/submodule permissions first; preserve the downloaded clone if recoverable. |
| `west` not found | Activate `zephyr_workspace/.venv` and install West in it. |
| `stm32h7b3i_dk` not found | Verify Zephyr revision and run `west update`. |
| CMake cannot find Zephyr | Run `west zephyr-export`, ensure the submodule and local CMake path exist. |
| Toolchain not found | Install the Windows Zephyr ARM SDK; rerun a pristine build. |
| `STM32_Programmer_CLI` missing | Install STM32CubeProgrammer and make its CLI discoverable. |
| ST-LINK device not found | Check board power, USB cable, driver, Windows Device Manager and other tools holding ST-LINK. |
| No UART output | Check correct ST-LINK COM port, 115200 8-N-1, reset after opening terminal, verify device is flashed. |
| LED not blinking | Check debug logs, board model, `led0` mapping and runtime boot. |
| LCD black | Verify display sample built for correct board, LCD power/backlight, LTDC and external SDRAM initialization. |
| Touch doesn't respond | Run the touch-specific sample; check FT5336/I2C/interrupt and chosen touch node. |
